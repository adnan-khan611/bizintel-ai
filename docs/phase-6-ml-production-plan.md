# Phase 6 — ML Productionization Plan

## 1. Objective

Phase 6 converts the validated forecasting workflow from Phase 5 into a reproducible machine learning production workflow.

The goal is to separate model training from model inference and establish a clean foundation for future API integration.

The Phase 6 workflow will be:

Canonical Data
→ Monthly Forecasting Dataset
→ Feature Engineering
→ Model Training
→ Model Artifact
→ Model Loading
→ Forecast Inference

The productionized ML workflow must remain deterministic, testable, maintainable, and independent from the API layer.

---

## 2. Current Phase 5 ML Pipeline

Phase 5 established the following forecasting components:

- Monthly merchandise revenue dataset builder
- Forecasting feature engineering
- Naive forecasting baseline
- Ridge regression forecasting model
- MAE evaluation
- RMSE evaluation
- sMAPE evaluation
- Expanding-window backtesting
- Next-month forecast generation
- Real Olist dataset verification

The current forecasting target is monthly merchandise revenue.

Revenue is calculated from canonical order-item price values represented internally in minor currency units.

The forecasting dataset uses the complete historical window from:

- 2016-10
- through 2018-08

Partial boundary periods were excluded from the forecasting window.

---

## 3. Productionization Goals

Phase 6 will establish the following capabilities:

1. Train the forecasting model through a dedicated training workflow.
2. Save the trained model as a versioned artifact.
3. Load a previously trained model without retraining it.
4. Generate forecasts using the loaded artifact.
5. Separate training logic from inference logic.
6. Make model configuration explicit.
7. Make model artifacts reproducible and traceable.
8. Add tests for training, persistence, loading, and inference.
9. Verify the complete workflow using the real Olist dataset.
10. Prepare the ML layer for future FastAPI integration.

---

## 4. Training vs Inference Separation

Training and inference must remain separate responsibilities.

### Training

Training is responsible for:

- loading prepared forecasting data
- generating forecasting features
- selecting complete training observations
- fitting the Ridge model
- recording model configuration
- saving the trained artifact

Training may require the historical dataset.

### Inference

Inference is responsible for:

- loading an existing model artifact
- receiving prepared forecasting features
- generating predictions
- returning forecast values

Inference must not retrain the model automatically.

This separation allows the future API to perform prediction without executing the training workflow.

---

## 5. Model Artifact Strategy

The trained Ridge model will be persisted as a model artifact.

The artifact must contain the complete fitted scikit-learn pipeline, including:

- feature scaling
- Ridge regression model

The artifact must therefore be usable without reconstructing the scaler manually.

The saved artifact should only be generated by the training workflow.

Inference should load the artifact and use it directly for prediction.

---
